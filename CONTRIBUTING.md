# Участие в разработке

Спасибо за интерес к Doobsky Zigbee Beacon.

## Перед началом

1. Создайте issue для ошибки, идеи или существенного изменения.
2. Для разработки используйте отдельную ветку от актуального `main`.
3. Не меняйте эталонную аппаратную схему без отдельного согласования владельца проекта.
4. Не меняйте характеристику `Fl(3).W.16.5s`, её временные константы или огибающую вспышки без обоснования и отдельной проверки.

## Локальная проверка

Перед pull request выполните:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
pio run -e esp32-h2-supermini-end-device
```

Все тесты и сборка должны завершаться успешно.

## Стиль изменений

- Делайте небольшие логически цельные коммиты.
- Используйте понятные сообщения коммитов, например:
  - `fix: preserve brightness after reboot`
  - `feat: add battery telemetry`
  - `docs: update hardware notes`
- Не смешивайте рефакторинг, изменение поведения и документацию без необходимости.
- Новое поведение по возможности сопровождайте регрессионным тестом.
- Не добавляйте бинарные сборки, дампы, секреты, токены и локальные IDE-файлы.

## Pull request

В PR укажите:

- что изменено;
- зачем это нужно;
- как проверено;
- влияет ли изменение на Zigbee, PWM, энергопотребление или аппаратную часть;
- требуется ли повторная аппаратная проверка.

CI должен пройти до объединения изменений.

## Аппаратные изменения

Для изменений питания, MOSFET, TPS61088, аккумулятора или измерительного делителя обязательно описывайте:

- исходное соединение;
- новое соединение;
- измеренные напряжения/токи;
- условия теста;
- возможные риски для ESP32-H2 и USB-порта.
